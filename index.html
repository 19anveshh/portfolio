001 DEEP DIVE EXPERIMENT

Building a RAG System for Indian Standards

Python FAISS Sentence Transformers FastAPI React
Documents BIS standards
Pipeline
Ingestion → Chunking → Embeddings → Retrieval → LLM
Interface React + FastAPI

Built a retrieval-augmented generation system that lets users ask questions about Bureau of Indian Standards documents in natural language. Instead of sending an entire document to an LLM, the system converts documents into searchable representations, retrieves the most relevant sections, and uses those sections to construct the answer.

The interesting part wasn’t the chatbot.

It was understanding everything underneath it — how documents should be split, how embeddings represent meaning, how FAISS searches that space, and how retrieval quality affects the final response.

WHAT I EXPLORED

⚡ Chunking

How much context should one chunk contain?

📐 Embeddings

How do words become vectors that a machine can compare?

🔍 Retrieval

How do you find the few pieces of a large document that actually matter?

🧠 Generation

How do you make the LLM answer from retrieved evidence instead of guessing?

WHAT I LEARNED

A RAG system is not just “LLM + PDF.”

It is a chain of decisions where a small mistake early in the pipeline can completely change the final answer.

That became the real experiment: understanding the pipeline well enough to know where the answer came from, why it was retrieved, and what could make it wrong.
